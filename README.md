# antd-builder

A visual builder for [Ant Design](https://ant.design) frontends. Think Figma, but the canvas renders
**real antd components**, and the output is production React code rather than a mockup.

When a page needs an element antd doesn't ship, you describe it in plain language and an LLM
(Gemini) generates a custom component from antd primitives. The new component then sits in the
palette next to the standard ones.

## Why

Most antd projects repeat the same work: put together layouts, forms, tables and modals, tune the
theme tokens, and then copy everything into code by hand. antd-builder aims to:

- **Speed up the standard.** Drag antd components onto a canvas, edit props in an inspector
  and set theme tokens visually.
- **Speed up the non-standard with an LLM.** Generate custom components that follow the
  project's theme and antd conventions.
- **Remove the design-to-code handoff.** The design is a typed JSON document, and code generation
  turns it into clean TSX.

## Core concepts

| Concept              | Description                                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Project**          | JSON document: theme (light/dark, compact, token overrides), pages, custom components, mock data, custom blocks and versions. Validated with Zod. |
| **Page**             | A tree of `BuilderNode`s (`component`, `props`, `children`).                                                                                      |
| **Canvas**           | Renders the tree live with real antd inside `ConfigProvider`, so what you see is what ships.                                                      |
| **Inspector**        | Prop editor for the selected node, driven by component metadata.                                                                                  |
| **Custom component** | A TSX component generated by the LLM, plus a props schema so the inspector can edit it.                                                           |
| **Mock data**        | Named sample API responses (JSON) that component props can be bound to.                                                                           |
| **Codegen**          | Turns a page into a React + TypeScript + antd component (Export code).                                                                            |

## Editing

- Drag components from the palette, or search it by name or description. Clicking an item (or
  <kbd>Enter</kbd> on it) adds it next to the selection instead: inside it when it fits, otherwise
  after it. The **Blocks** group at the top adds ready-made fragments: a page header, a sign-in
  form, a stats row, a user table, pricing plans, an FAQ, a contact form and a footer. The data
  blocks bring their own mock data, already bound, and fit a phone screen.
- **Save as block** in the inspector keeps the selected component and its children as your own
  block, under **My blocks** in the palette.
- Select components on the canvas or in the **Layers** outline, then edit them in the inspector.
  The outline can be filtered by component or text, and its layers have the same right-click
  menu as the canvas. The inspector shows the component's path (Page / Card / Button) for
  selecting an ancestor; <kbd>Shift</kbd>+<kbd>Enter</kbd> / <kbd>Enter</kbd> move the selection
  to the parent or the first child, and <kbd>↑</kbd> / <kbd>↓</kbd> to the previous or next
  sibling. Components with many props get a filter, and **Reset props** restores the
  defaults.
- Duplicate, copy/cut/paste, reorder (Alt+↑/↓) and delete the selection, from the inspector, the
  keyboard or the canvas's right-click menu. **Wrap in** Flex, Card or Space puts a component in a
  new container (<kbd>Ctrl/⌘</kbd>+<kbd>G</kbd> for Flex); **Unwrap** replaces a container with its
  contents. These commands live in `src/components/nodeCommands.tsx`.
- Undo/redo covers page, theme, mock data and block edits. The buttons name the step they take
  ("Undo Add Button").
- The **Theme** tab starts from presets (Ocean, Forest, Midnight…) that you can fine-tune.
- **New** (header) starts an empty project after a confirmation. Your saved blocks carry over.
- **Version history** (header) saves named snapshots of the project and restores them. Restoring
  can be undone. <kbd>Ctrl/⌘</kbd>+<kbd>S</kbd> saves a version from anywhere in the editor.
- The toolbar above the canvas sets its width: Desktop (full width), Tablet (768px) or Mobile
  (375px). Grid columns have per-breakpoint spans (`xs`–`xl`), and the canvas applies the span
  antd would use at that width. Other antd features based on breakpoints
  (`Grid.useBreakpoint`, for example) still follow the browser window.
- **Preview** shows the page as users see it, without panels, selection or drop placeholders.
  Press <kbd>Esc</kbd> to return to editing.
- Press <kbd>?</kbd> (or the header's help button) for the full list of keyboard shortcuts. It is
  generated from `src/components/shortcuts.ts`, so the list stays current.

## Mock data

Mockups can show realistic API data instead of placeholders:

1. In the **Data** tab, add a data source and paste a sample API response as JSON. Each source
   has a name such as `users`, which must be a valid JavaScript identifier. Or use **Import from
   URL**: the server fetches a public API's JSON (so CORS doesn't get in the way) and the source is
   named after the URL. Imported sources remember the URL, and the ↻ button fetches it again.
2. In **Properties**, the 🔗 button next to any prop binds it to a data source. An optional
   path picks part of the response: `0.name`, `meta.total` or `length`. Path suggestions list
   only values that fit the prop. A preview shows the value, or explains why it doesn't fit.
3. The canvas shows the bound data live, and editing a response updates every component bound
   to it. The table button on a data source adds a table of its rows in one click: columns come
   from the rows' fields, and the rows can also be a list inside the response (`{ items: [...] }`).
4. **Export code** declares the data sources the page uses as `const`s and references them,
   for example `dataSource={users}` or `{users[0]?.name}`. Replace them with real data fetching.

Mock data is saved with the project and covered by undo/redo.

## Sharing and export

- **Share → Create link** uploads a read-only snapshot of the project and gives you a link
  (`/s/<id>`). Viewers see the page in preview, can switch the canvas width, and can **Open in
  editor** to copy it into their own browser. If they already have a project, they are asked
  before it's replaced. Snapshots don't change: create a new link to send later edits. Version
  history isn't shared. The page title and link preview show the project's name.
- Links expire after 30 days (`SHARES_TTL_DAYS`). The Share dialog lists the links created in
  this browser, with their expiry, to copy again or delete. Deleting needs the token the server
  returned when the link was created, which only this browser has.
- **Export code → Download Next.js project** downloads a ZIP of a runnable Next.js app: the page,
  its mock data as `data/*.json`, stub API routes serving that data (`GET /api/<name>`), a layout
  with the antd registry, `package.json`, `tsconfig.json` and a README. A unit test type-checks the
  generated project.

## Component coverage

The palette offers every component antd exports, including sub-components such as
`Layout.Sider`, `Input.Search` and `DatePicker.RangePicker`. A test fails when an antd upgrade adds
a component the registry doesn't cover. The only exclusions are `App` and `ConfigProvider`
(providers), `Grid` (hook namespace), and the deprecated `BackTop` and `List`, which are replaced by
`FloatButton.BackTop` and `Listy`.

Some components behave differently on the canvas so they can be edited in place. The exported code
is unaffected:

- `Modal`, `Drawer` and `Tour` show their panel inline instead of covering the editor.
- Trigger components (`Dropdown`, `Tooltip`, `Popover`, `Popconfirm`) open from their child as
  usual. Their "Always open" prop keeps them visible while you design.
- Fixed-position components such as `FloatButton` are positioned within the canvas.

Each component has its own test suite, which:

- renders it with its defaults, with every inspector value and with children, failing on any React
  or antd warning (so deprecated props are caught),
- checks it has an inspector field for every prop,
- exports it to JSX,
- type-checks the export against antd's types.

An e2e test also drops each component from the palette.

## Architecture

```
antd-builder/
├── src/
│   ├── app/                    # Next.js App Router
│   │   ├── page.tsx            # Editor entry
│   │   ├── error.tsx, global-error.tsx, not-found.tsx
│   │   ├── s/[id]/             # Read-only view of a shared project
│   │   └── api/
│   │       ├── ai/component/   # POST: generate a custom component with Gemini
│   │       ├── data/fetch/     # POST: fetch sample JSON from a public URL
│   │       ├── export/         # POST: project → Next.js app ZIP
│   │       ├── shares/         # POST: share a snapshot; GET [id]: read it
│   │       └── health/         # GET: liveness probe
│   ├── components/             # Editor UI: palette, canvas, inspector (client components)
│   └── lib/
│       ├── schema/             # Project / page / node types + Zod validation
│       ├── registry/           # antd component metadata: props, defaults, nesting rules
│       ├── tree/               # Page root, immutable page-tree operations, drop resolution
│       ├── editor/             # Editor state (Zustand), undo history, drag-and-drop planning
│       ├── search/             # Search matching for the palette and inspector
│       ├── project/            # Project file: build, validate, read from API requests
│       ├── codegen/            # Page tree → TSX
│       ├── ai/                 # Gemini calls (server-only)
│       ├── remoteJson/         # SSRF-guarded JSON fetching (server-only)
│       ├── shares/             # Shared snapshot storage on disk (server-only)
│       ├── scaffold/, zip/     # Next.js project files and the ZIP writer
│       ├── rateLimit/          # Per-client request limits for API routes
│       ├── format.ts           # Date formatting for the reader's locale
│       ├── csp.ts              # Content-Security-Policy builder
│       └── env.ts              # Validated server environment (server-only)
│   ├── proxy.ts                # Per-request CSP nonce
│   └── instrumentation.ts      # Startup checks (fails fast on invalid env)
├── e2e/                        # Playwright tests
└── .github/                    # CI + security workflows, Dependabot, CODEOWNERS, templates
```

```
 Browser (client components)                    Server (route handlers)
 ┌──────────────────────────────────┐           ┌──────────────────────────────┐
 │ Palette ─▶ Canvas ◀─ Inspector   │  fetch →  │ POST /api/ai/component       │──▶ Gemini API
 │              │                   │           │   zod-validated input        │
 │              ▼                   │           │   lib/env (server-only key)  │
 │ Project JSON (lib/schema)        │           └──────────────────────────────┘
 │   └─▶ lib/codegen ─▶ TSX export  │
 └──────────────────────────────────┘
```

- antd's CSS-in-JS is rendered on the server via `@ant-design/nextjs-registry`. The editor is a
  client component, because the canvas, drag and drop, and inspector are interactive.
- Secrets stay on the server. `lib/ai` and `lib/env` import `server-only`, so importing them from a
  client component fails the build.
- Environment variables are validated with Zod when the server starts, not at build time. One
  build can be promoted through dev, staging and prod, and a misconfigured instance exits with code
  1 instead of serving errors.

## Getting started

Requirements: Node ≥ 24 LTS (see `.nvmrc`) and pnpm 11 (`corepack enable`).

```bash
pnpm install                     # also installs git hooks
cp .env.example .env.local       # add your GEMINI_API_KEY
pnpm dev                         # http://localhost:3000
```

### Environment variables

| Variable          | Required | Default            | Purpose                               |
| ----------------- | -------- | ------------------ | ------------------------------------- |
| `GEMINI_API_KEY`  | yes      | —                  | AI component generation. Server-only. |
| `GEMINI_MODEL`    | no       | `gemini-3.8-flash` | Model used for generation             |
| `SHARES_DIR`      | no       | `.data/shares`     | Where shared project snapshots live   |
| `SHARES_TTL_DAYS` | no       | `30`               | Days a shared link works              |

Never prefix secrets with `NEXT_PUBLIC_`. Doing so inlines them into the client bundle.

### Scripts

| Command          | Description                                                         |
| ---------------- | ------------------------------------------------------------------- |
| `pnpm dev`       | Dev server with Turbopack                                           |
| `pnpm build`     | Production build (standalone output)                                |
| `pnpm start`     | Run the production build (`.next/standalone/server.js`)             |
| `pnpm lint`      | ESLint (`lint:fix` to auto-fix)                                     |
| `pnpm typecheck` | Generate Next route types and run `tsc`                             |
| `pnpm format`    | Prettier write (`format:check` in CI)                               |

## Quality gates

- **Pre-commit:** lint-staged runs ESLint (`--max-warnings=0`) and Prettier on staged files.
- **Commit messages:** [Conventional Commits](https://www.conventionalcommits.org), enforced by
  commitlint locally and in CI.
- **CI** (`.github/workflows/ci.yml`) runs on every PR and every push to `main`:
  - production dependency audit (fails on high/critical)
  - lint, typecheck, format check, and build
  - unit tests with coverage; CI fails below 80% on lines, branches, functions or statements
  - Playwright e2e against the production build, including CSP and error-page checks
  - commitlint over the PR's commits
- **Security** (`.github/workflows/security.yml`) runs on every PR, on every push to `main` and
  weekly:
  - CodeQL static analysis (`security-and-quality` queries)
  - dependency review on PRs (blocks new high-severity vulnerabilities)
  - TruffleHog secret scan of the git history
  - Trivy scan of the Docker image (fails on fixable high/critical; full report in code scanning)
- **Supply chain:**
  - every GitHub Action is pinned to a commit SHA, and the Docker base image to a digest
  - Dependabot keeps those pins up to date and opens grouped weekly npm updates
  - pnpm blocks freshly published packages (minimum release age) and allows install scripts only
    for packages listed in `pnpm-workspace.yaml`
  - accepted audit exceptions live in `pnpm-workspace.yaml` (`auditConfig.ignoreGhsas`), each
    with a written justification

> CodeQL and dependency review on **private** repositories require GitHub Advanced Security
> (GitHub Code Security).

## Deployment

The app builds to a self-contained Node server (`output: 'standalone'`).

```bash
docker build -t antd-builder .
docker run -p 3000:3000 -e GEMINI_API_KEY=... antd-builder
```

The image runs as a non-root user, has a `HEALTHCHECK` on `/api/health`, and exits at startup if
required env vars are missing. Pass configuration as runtime env vars rather than baking it into
the image.

Shared snapshots are files in `/app/.data` (a declared volume). Mount one to keep share links
working across container restarts, for example `-v antd-builder-data:/app/.data`. Rate limits are
kept in memory per instance.

### API protections

- **Rate limits** per client per minute: URL fetching 30, deleting shares 30, export 20, sharing
  10, AI generation 10.
  Beyond them the API answers `429` with `Retry-After`. Clients are told apart by the first
  `X-Forwarded-For` address, so run the app behind a proxy that sets that header.
- **URL fetching** (`/api/data/fetch`) refuses loopback, private, link-local (cloud metadata) and
  other internal addresses. The check runs when the socket connects, so DNS rebinding can't get
  around it, and it is repeated after each redirect. Responses are capped at 1 MB and 5 s.
- **Shared projects and exports** are validated like an opened project file and limited to 2 MB.
  Share ids are 128-bit random, and shared pages are marked `noindex`.

### Security headers

- **Content-Security-Policy** is set per request in `src/proxy.ts`:
  - Scripts must carry that request's nonce (`'strict-dynamic'`). Next.js adds the nonce to its
    own scripts automatically.
  - `style-src` allows `'unsafe-inline'`, because antd and React set inline `style` attributes
    that a nonce can't cover. Script injection is still blocked.
  - Because the nonce changes on every request, every page renders dynamically.
- **Other headers** are set in `next.config.ts`: HSTS, `X-Frame-Options: DENY`, `nosniff`,
  `Referrer-Policy` and `Permissions-Policy`. `X-Powered-By` is removed.
